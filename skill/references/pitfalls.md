# 失败触发条件与定位

| 现象/触发 | 已知证据 | 排查顺序与边界 |
|---|---|---|
| CRC 正确但文件仍不完整 | b535…：835 条记录，缺唯一帧 378/379 | 检查唯一帧集合、重复帧、偏移和最终 SHA；不能只看 CRC 个数 |
| 中途退出、未进入 HDMI | d2bd…：RF 帧 342 CRC 拒绝 | 先查 RF/同步与信道；页面“native receiver failed”不是 HDMI 根因 |
| 天线摆放后成功率变化 | 同 18 dB、同 IQ，路径功率差约 7.5→16 dB | 核配置回读、接头、极化和位置，再比较接收估计；不是必然需要加大发射增益 |
| 采集上限不足/启停不匹配 | 历史 1024 块硬限制，后来验证 2048/5120 生命周期 | 采集池、块序、退出和边界必须一起测，不能只改常量 |
| 画面闪动但文件/像素正确 | 实收与隔离轮视觉不同；提优先级只减轻 | 保留视觉异常，隔离调度/中断/显示；不得倒推 MIMO 解码错误 |
| 接收结束但设备没有画面 | 冷启动发送窗口错过、探针或完整性门禁失败均曾发生 | 拿日志确定停在哪层；为独立冷启动预留时间，不重复盲发 |
| 命令回包缺失/乱码 | picocom 并读、ttyACM0→ttyACM1 曾发生 | 固定设备 ID、独占锁；先只读核设备，不同时开两个读者 |
| 文件权限校验误失败 | 解包安全收紧 0664→0644 | 按角色检查 SHA/大小/必要执行位；不能错误要求原写权限 |
| 仅看两秒视频误判静止 | 十帧变化太小，用户未看清 | 选明显运动、延长观察；未看清保持未确认 |
| 源副本与已验收 bit 不匹配 | 本次先发现四处 vendor 输入不同，后从原归档找回 | 按综合输入 SHA 搜索精确归档；最终 102 条 vendor/18 项配方匹配；不能改哈希冒充闭合 |

每条是特定证据下的经验，不是所有板卡的根因结论。自动重试、发射、写卡权限由当前用户决定。

## 打包后的真实入口检查

- 有些 Buildroot 根树的 Python 标准库只有 .pyc。按“缓存”扩展名删除会使 encodings 导入失败；应保留运行闭包并在隔离恢复目录运行真实解码器。本版补齐 1025 个运行文件，25 AU ARM NULL 解码通过。
- 最终综合未采用的 RTL 也可能被 Tcl 无条件 add_files。精简包应验证新工程/BD 生成，而非只核最终综合输入哈希。本版从冻结包恢复 rf_static_clkdiv.v，保持原 SHA。
