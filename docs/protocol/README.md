## 1. 固定需求与不做事项

- 硬件固定：PC＋现有X310/CBX，接收端ZedBoard XC7Z020＋FMCOMMS3/AD9361；不添计算/解码硬件。以现有Vivado2025.2、匹配Linux内核为工程基线，构建依赖必须可定位，不引用别的电脑临时目录。

- 无声视频；首版按1024×600编码/传输/HDMI显示、真实20fps设计。用户早前允许最低640×360，但最新要求首轮按1024×600施工：不以偷偷降分辨率、重复帧或插值帧冒充达标。
- 室内约10m、无穿墙要求，摄像头通常固定、画面内目标运动；偶尔大幅转向后静止，转向期间允许质量下降。两端/天线小范围移动须能重新跟踪信道。
- 延迟目标：采集到实际HDMI新帧约3秒以内，不主动等待3秒开播；不建“攒满数秒才播放”的池。保留有界的重组、纠错、解码、显示缓冲。过载丢过期内容、跳到可恢复的新画面，不无限排队。

- 阶段一先不实现/实测反向RF反馈和前后向TDD；阶段二必须实现单路低速反向RF反馈，前后向时分，不依赖反向网线，且真实影响关键帧请求/纠错统计/有限重传。阶段一的预留接口不算反馈功能已完成。

### G0-A 视频与解码预算

用户已允许替换原指定素材`G:/qq_message/mmexport1793486677009.mp4`；选择当前可读取的代表性10秒素材，记录来源/版本、运动和场景突变，后续对照固定使用同一输入，不将未获发布许可的原视频随公开仓库上传。将10秒素材重采样到20fps、1024×600、BT.601、baseline、无B帧。比较短GOP P帧＋周期IDR与受控帧内刷新，锁定一种；不能用全I帧高开销作为未经比较的默认方案。

测量平均、95/99分位、最大AU和slice字节数、短窗码率、关键帧突发、可辨认程度；抽帧接触表和完整本地播放均检查，灰屏/严重马赛克即失败。试验编码目标先扫0.6/0.9/1.2Mbps，数字为待测候选，不能以任一档画质必达标作承诺。场景突变也进入码率测试。以实际可用画质所需码率锁定R_video。

### G0-B PHY主选与计算

首选候选：单载波QPSK、4MSPS、每符号4样本、1Msym/s，使用两路TX/RX。中心频率以已测5.5GHz为开发配置；其他频点仍需匹配当地授权及天线/前端能力。不以提高增益当作可靠性设计。

实现2×2空间复用：两路独立符号、每接收天线同时观察两路；用时分正交训练估计4个复数信道系数，以导频连续跟踪。X310两个发射支路的实际LO/相位关系必须查明：不能默认CBX两路相位相干，也不能仅做公共NCO就假定消除全部偏差。预算并验证各流残余相位/CFO；接收路径的公共采样时钟与发送采样时钟误差也须跟踪。

若两路分离/相位跟踪在固定设备上不能可靠达到预算，报告实测证据与改进方案；不自行把正式链路改为Alamouti等单流分集或SISO。已有此类比较仅作为历史/诊断证据，不维护并存的生产电路；冻结后不在施工中暗自切换模式。

容量公式：`R_video_limit = N_stream × 2 × R_sym × η_phy × η_tdd × r_fec × η_packet`。

- η_phy含前导、训练、导频、物理保护间隔；η_tdd在阶段一表示实际前向占空比（无反向窗口时不虚扣反馈损失，主动预留静默窗口须扣除），阶段二再包含实测反馈和收发切换损失；r_fec是源/总包比例；η_packet含所有头、CRC和尾包浪费。每项必须由对应阶段的最终帧格式算出，不可重复扣除或漏算。
- 例：双流毛4Mbps，假设η_phy=.80、η_tdd=.90、r_fec=.75、η_packet=.94，视频上限约2.03Mbps。这是预算示例，不是已定效率或实测吞吐；若可用视频需要1.2Mbps，则平均约59%负载，有约41%头部余量。分集单流等效在同假设下约1.02Mbps，不足以给1.2Mbps素材留裕度。
- 阶段一冻结要求：至少30%的持续净吞吐裕度，并给99分位突发设置可满足3秒截止的有界预算。同时冻结采样/符号率、RRC/带宽、定点位宽、训练与导频密度、帧长、FEC、前向调度周期、DMA粒度及无反馈恢复策略；另列阶段二反馈/TDD占用与资源预留估算，最终切换时隙待阶段二实测冻结。4MSPS方案不够时，仅在G0中评估下一固定采样/符号率候选及收发硬件、PS/PL吞吐约束；不盲目升时钟。
- 实测约15%包丢失并非独立像素擦除。必须用真实缺包序列加随机及突发模型评估FEC尾部概率，不能只按平均15%定保护率。未经测试不能承诺“丢包不影响画面”。

### G0-C 阶段一无反馈运行与阶段二预留

阶段一冻结无反馈的前向调度周期、会话广播/参数重复、周期可恢复点和失锁恢复等待上限。PC不等待板端ACK、NACK、关键帧请求或反馈RX就绪；板端保持接收，反向TX关闭。G0-A比较的短GOP或帧内刷新策略必须在无反馈损失注入下证明可有界恢复，不能把人工关键帧命令或反向网线当正式恢复路径。

在预算表中保留将来反馈所需控制接口、吞吐和资源空间，估算值明确标注未实测；不将当前前向容量全部用满后宣称未来反馈不会影响20fps。

### 阶段二前置测量：时分与反向RF

阶段二以固定超帧为基准，先评估20ms等候选；前向、guard、单路反馈、guard的时长由AD9361/X310实际切换和UHD定时收发测量确定，不能用Linux sleep/ioctl承担微秒精度时隙。预留90%前向时间仅为预算目标，切换超过预留就需重新核算、优化并冻结阶段二profile，不降低视频目标。

阶段二超帧内由PC UHD设备时间调度；板端PL状态机按恢复出的帧边界计时，控制预配置的收发切换。频率尽量不在每个时隙重新调谐；明确ENSM、收发隔离、TX静默和重捕获窗口。PC同时具备反馈RX实现，不仅TX。反向前导和控制调制可借用前向简化模块，单流低速QPSK、短固定包、CRC与小型编码/有限重复，不运行反向视频链。

两阶段都必须在实发前核对发送授权、功率/增益限值、天线端口/负载和合规频段。当前接线以用户更正为准：FMCOMMS3 TX1A未接天线，反向RF实测延期；阶段一板端反向TX始终关闭；阶段二重新确认端口/天线/授权后，自动开机接收默认TX关闭，只在已同步分配的反馈时隙按允许参数发控制包。

## 4. 完整架构和所有权

前向视频链路属于阶段一；图中的反向反馈链路及反馈驱动重传属于阶段二。

```text
摄像头/固定素材 → PC持久采集/编码 → NAL/slice打包 → FEC/交织
       → 有界截止调度 → UHD定时双路TX → 真实空口
       → AD9361双RX/LVDS → CDC/采样FIFO → 同步/AGC策略/频偏和采样漂移跟踪
       → 匹配滤波/定时 → 2×2信道估计/相位跟踪 → ML检测/解映射
       → 包CRC/分类 → PL块缓存/FEC恢复 → AXIS批量DMA环 → PS按slice重组
       → 持久H.264解码/错误隐藏 → 像素转换/双或三缓冲 → 原HDMI KMS/物理ACK

PS统计/恢复请求 → 小控制队列 → PL定时单路反馈TX → AD9361
       → 反向空口 → X310 RX → PC反馈接收 → 有界重传/刷新关键帧
```

PL负责高采样率、确定时序、包级FEC，以及阶段二的小型反馈TX；PS负责视频重组、解码与显示调度；PC负责编码、前向FEC/波形，以及阶段二的反馈决策。先使用C/C++常驻数据面，Python限配置/实验/分析，不在视频热路径逐像素处理。

双流QPSK的ML候选符号向量为16种，求`||y-Hx||²`最小；定点流水/共享DSP设计，不能用CPU逐符号发任务。50MHz对1Msym/s每符号有50周期，但要求调度II最多25周期以留至少2倍算术服务裕度；计算实际DSP复用和溢出/量化误差后冻结，不能靠纸面周期数推定整体达标。滤波/NCO/同步/估计分别给出II、FIFO深度和最坏背压预算。

## 5. 新视频协议和恢复语义

不兼容旧MRF1/RVF2作为默认；定义全新版本，PC/PL/PS用同一机器可读schema生成常量、打包器、RTL package和golden vectors。

分层为：物理训练/导频 → link packet → FEC源/修复符号 → video slice fragments → H.264 AU。一个slice不是固定方形像素块，帧间预测也会传播损伤；不承诺丢一个包只坏对应像素。

链接头候选32B，小端序：magic4、version1、type1、flags2、session4、superframe4、packet_seq4、frame_id4、fec_block_id4、symbol_index2、payload_len2，末尾CRC32 4B覆盖头和实际payload。视频源符号内部描述至少包含NAL/slice标识、fragment索引/offset、声明长度、采集时间和frame截止时间；具体位宽在G0 schema中锁定。流描述含分辨率、色彩、编码profile、时钟单位、FEC参数、GOP/恢复模式。不能因仅32B头未包含所有应用字段而漏计应用头。

当前FEC候选为每块RS(20,32)、固定512B编码符号（源比例.625），固定8-bank不改变该参数或纠错能力；早期512～1024B及.70～.80源比例仅为历史预算候选，不再维护并行实现。FEC块跨有限个帧/切片交织，不能无限等待；最终profile仍须真实损失、吞吐和截止验证。CRC不通过记为擦除，不将坏比特当作正常数据；FEC恢复成功做必要块/包一致性检查，不做文件SHA。

切片/参数集边界要可辨识；关键参数/恢复点不依赖唯一一包。视频重组不能强制整AU所有分片齐全才准入：FEC后完整slice可按解码器可支持的受损AU方案提交，明确受损标志与缺失范围；头/SPS/PPS或必要slice头缺失时跳过该单元并记录恢复需求；阶段一等待周期参数/可恢复点，阶段二再发送恢复请求，不让helper整个退出。

短GOP/周期刷新防传播；普通P帧丢失后根据参考关系等待周期恢复点（阶段一）或请求恢复点（阶段二），不能任意跳压缩P帧并声称下帧独立。残缺解码允许保留旧区域/空间或时间错误隐藏；优先简单、可测、低开销算法，不加入大模型CV，不把灰屏/重复帧算有效新图。

阶段二反向反馈字段：session、超帧号、反馈seq、接收最高packet_seq、缺失块/符号有界位图、FEC恢复/残余擦除、CFO/时序/通道质量摘要、接收队列水位、关键帧请求、接收时间。反馈带ACK/超时语义，无反馈时继续前向并按固定保护运行，不互相等死。重传只补播放截止前有价值的片段；旧数据超过截止即放弃，不因追求完整性制造3秒以上积压。

初始时间同步：PC时间映射到UHD设备时间，板端以超帧序号+已知采样周期建立映射，阶段二再通过反馈校正往返时序；阶段一使用单向映射并报告时钟不确定度，不依赖往返测量才能启动。单端日志时间差不能冒充端到端延迟；验收另用摄像头拍计时器与屏幕同框的方法交叉验证。

## 6. 流水线、缓冲和资源预算

所有阶段可同时处理不同帧；仅有算法依赖处等待，不设全链路逐帧栅栏。每段都有独立的有界输入队列、对象生命周期和测量接口。

- PC编码/分包/UHD发送各为常驻工作线程或明确阶段；阶段二新增常驻反馈接收，不作为阶段一启动或调度依赖；不每帧打开USRP、不每包重调LO、不把所有IQ预生成成巨型文件作为摄像头运行方式。
- PL ADC域→处理域用已验证CDC FIFO，复位每域同步释放；异步单bit与多bit握手分别约束。FIFO满记录真实丢样和epoch fence，不能将被迫丢掉的数据宣称连续。
- DMA采用循环/SG环批量提交，单一owner，一次性读出每条记录；不逐符号START/WAIT/READ，不重复读取同一结果；中断可合并且必须给出最大交付延迟。
- FEC/重组/解码/显示分离；截止和队列水位决定丢旧帧/记录恢复需求；阶段一等周期恢复点，阶段二才经RF请求IDR。收到一张就绪不等于等待全窗口全部完成才交HDMI。目标帧间隔50ms，处理时间与排队时间分别统计。
- 压缩包/像素缓冲放DDR，不占大量BRAM；当前HDMI物理契约为XRGB8888/64-bit AXIS，一帧2457600B，三帧估算7372800B，另计页对齐、解码参考帧及转换池。RGB565一帧1228800B只适用于中间格式。帧缓冲用DMABUF或等价明确所有权机制，避免多次RGB全帧复制；帧只在真正不再被scanout使用时回收。
- 双核PS分工建议：DMA交付/视频重组/低速控制一路、解码/转换/显示一路；实测后绑定亲和性，禁止推测分核等于吞吐翻倍。解码线程数和NEON转换用基准选择。
- PL当前规划软目标：LUT≤85%（45,220/53,200），FF≤65%、BRAM≤70%、DSP≤75%保持；旧LUT70%仅为历史对照，不为回到旧目标反复优化。按实测组件、未完成核心、整机集成、阶段二估算分别建账，后续新增资源单独列明。先实现核心链路，再针对真实容量/吞吐/时序瓶颈优化；物理容量、完整时序/CDC/IO及性能仍须通过，软目标放宽不等于完整资源预算通过。
- 50MHz是处理时钟起点；必须重新满足setup/hold、外部LVDS输入输出时序和CDC，不能拿旧报告替代。阶段一完成DDR/HDMI与前向RF并发压测后，才给出该阶段资源结论；阶段二加入反馈后须重新并发压测，不沿用阶段一结论代替。

## 7. 可接受数据与错误处理（避免过度防御）

默认热路径只校验版本/类型、长度/范围、必要CRC、对象身份及内存所有权。合法分辨率/码流由会话协商配置，不能把可接受的多slice、乱序、重复、短时缺失一律当FATAL。

重复包忽略、乱序有界重组、CRC坏包转擦除、FEC尽力恢复、迟到/过期数据丢弃、失锁自动重捕获。局部缺包或单帧解码失败不得直接导致进程退出、无限阻塞或每次重启整机：超过恢复能力时允许错误隐藏、跳过损坏内容或有界等待周期恢复点，不强制整AU所有分片齐全；如实统计花屏、冻结和帧龄。阶段二再发送刷新请求。未知可选扩展按长度跳过；不兼容主要版本拒绝该会话并给原因。结构截断/越界不能交给DMA/解码器；限定最大NAL/AU/块数/队列、处理截止，防无限分配。

不做SHA启动门禁、反复扫描静态文件、每帧全链路校验脚本、无限重试、每次异常重启整机。保留协议CRC、FEC一致性、DMA边界、缓存上限、射频TX权限/配置限制。恢复是明确状态机，不是堆叠try/except或吞错后报成功。

## 8. Agent调试接口（正常运行不依赖外部电脑）

统一`session/frame/packet/slice/fec_block/superframe`标识；事件含domain、epoch、sample index、单调时钟、原因码；计数定义必须区分脉冲/唯一包/唯一AU。每阶段输出输入量、输出量、拒绝分类、延迟分布和队列高水位。

必须保留基本计数、必要定位及可脚本化CLI/JSON接口；非必要大型缓存/冗余快照/详细追踪按第6节列项精简或延期，不作为核心视频共同阻塞项：

1. RF身份、LO/增益/采样率、LVDS PN/通道映射、实际clock/ready。
2. ADC连续采样的有界开发抓取/离线重放入口；抓取时保留足够前史、真实连续坐标及loss标志，禁止短片冷态重放误诊。常驻多帧flight recorder和宽状态快照可精简或延期，必要数据对照证据仍须提供；诊断不得反压业务。
3. 同步候选/通过/失败、CFO/残差、SFO/定时相位、4个H系数/条件数摘要、ML饱和/度量摘要；错误分类直达CRC/包头而非只读“最后错误8”。
4. 包/擦除/FEC恢复前后镜像，slice缺失位图，解码输入和状态输出；默认仅计数，按需有界抓取，不重复读取业务DMA。
5. 解码/补全/转换/显示阶段时间戳和真正HDMI边界ACK；截图为可选观察动作，不能影响正常显示生命周期。
6. 阶段一报告无反馈模式、板端TX关闭及本地恢复需求，反馈状态标为未启用/未验证；阶段二再提供反馈时隙、TX启停、PC收包/ACK、恢复请求是否生效和连续时隙丢失观察。

离线入口支持ADC→RTL、包序列→FEC/桥接、AU→native ARM解码、帧缓冲→HDMI分段重放；提供golden和损失注入。golden仅作输出对照，不能注入接收算法估频/定时。诊断开关和日志有成本预算；满诊断队列丢诊断记录，不拖业务，且标记diagnostic_drop。

## 9. 两阶段施工与通过条件

### 阶段一：无反向RF反馈的单向视频（G0～G7）

- G0：读取官方前端/时钟资料；测编码、本地ARM20fps、双支路相位/CFO与前向链路；完成资源、前向调度及可靠吞吐预算，冻结无反馈完整profile、schema、接口、周期恢复策略和验收容差。反馈/TDD只做接口和预留预算，不要求其测量完成；任何硬性视频目标不可行先报证据，不用演示降级冒充完成。
- G1：PC/PS/PL共同golden：随机/突发擦除、CRC损坏、乱序/重复/迟到，FEC与参考一致；多slice损伤和超过纠错能力不结束进程、不无限阻塞、不重启整机、不强制整AU齐全，P帧依赖及无反馈周期恢复正确；3秒截止/过载丢弃、缓存上限/所有权和花屏/冻结统计有测试。明确验证无反向RF ACK、无反馈RX、无远程关键帧请求时仍持续发送/接收，不能以人工恢复代替。
- G2：完整PL前向2×2双流接收、ML、CRC/固定8-bank FEC和包DMA逐模块及全链并发仿真；固定8-bank须验证满队列/突发吞吐、第九任务的有界处理、取消重用及排队/活动截止。覆盖ADC PN、采样漂移、独立TX残余CFO、移动信道、MIMO退化、gain/饱和、FEC不可恢复、DMA满环/取消/复位及板端反向TX始终关闭。反向TX/TDD模块延期，不以stub冒充其已实现；不再测试16-bank。
- G3：新PS内核/设备树/运行时、PC摄像头到UHD常驻前向发送、真实ARM解码/补全/显示全部接入；阶段一必需模块不使用stub。无黑盒、无缺驱动/固件/资源文件，前向不依赖反馈线程、反向RF ACK或控制队列消费。
- G4：全量综合实现/bitgen，所有约束满足、外部IO/CDC审计通过、资源预算复核；生成注明阶段一/无反馈profile的BOOT、kernel、DTB、rootfs、应用/驱动和SD安装入口。新空白SD完整部署与现有卡可恢复更新入口说明清楚；最后统一一次必要文件对照，不跑SHA。
- G5：实板先接收/低风险身份→LVDS PN/ADC→物理包→FEC→视频→HDMI并发；先受控衰减链路，再约10m室内天线。核对板端TX关闭和无反馈恢复；冻结软件/硬件身份，不能混不同版本报告。反向反馈与TDD实测单列为阶段二待完成。
- G6：固定10秒素材以1024×600、20fps编码，至少连续循环形成≥60秒短验收窗口；摄像头实际实时采集另测，源内容必须真实经2×2双流RF流水线而非板端预存。记录真实新帧数、帧间隔/冻结、源帧龄、质量样例、RF/FEC残余损失及CPU/队列；正常静置目标真实新源帧20fps，窗口容差和仪器分辨率在G0写明，不临时降低标准；约3秒延迟内，转向允许画质下降但记录恢复过程。全程不依赖反向网线、RF反馈或人工关键帧指令。
- G7：拔掉开发线、断电再上电，从SD自动初始化和接收/解码/HDMI；发送端迟启动、停发和恢复均通过，板端反向TX保持关闭。数小时温升/耐久不作首阶段条件，但不可有一停发就死锁等基本问题。

### 阶段二：单路反向RF反馈与TDD

- B0（测量与再冻结）：实测AD9361 ENSM、X310/UHD收发切换、端口/天线及guard；冻结反馈PHY/字段/编码、ACK/超时、重传次数/字节/截止、TDD时隙和更新profile。重新核算可靠净吞吐、至少30%持续裕度、资源及3秒延迟，不把阶段一预留估算当实测。
- B1（完整实现与仿真）：实现C06、R11和相关反向TX/RX、PS控制邮箱及PC编码器/调度联动；覆盖反馈丢失/重复/迟到、TDD边界/失步禁TX、TX结束回RX及业务并发。预留接口或模拟反馈不算反向RF已完成。
- B2（真实功能验证）：真实RF反馈驱动关键帧请求、纠错统计及截止前有价值的有限重传；证据覆盖“板端请求→PC收到→编码器/调度动作→板端恢复”。反馈全丢也继续前向固定保护，不永久等ACK、不无限重试；不依赖反向网线。
- B3（整机重新签核）：对更新后的完整PC/PL/PS/profile重做G4～G7适用验收，包括综合/bitgen/IO/CDC、启动/SD包、并发RF/HDMI、≥60秒真实20fps素材与摄像头、约3秒延迟及无开发线断电冷启动。不能拿阶段一报告替代加入反馈后的性能与独立运行验收。
