## 0. 阶段能力声明与无反馈语义

会话描述必须声明profile ID和`feedback_enabled`能力（实际字段编码由对应schema冻结，不改变下述32B link头、40B视频头布局）。阶段一固定`feedback_enabled=false`：板端反向TX保持关闭，不启动反向调制/反馈时隙，PC不等待反向RF ACK、缺包位图、反馈RX或远程关键帧请求即可持续发送。为未来反馈保留类型、接口及容量/资源预算，不把预留接口、空线程或虚构ACK当成功反馈。

阶段一采用固定8-bank FEC、周期会话描述/SPS/PPS及周期可恢复点，接收端错误隐藏、失锁自动重捕获和有界等待；恢复需求仅记录本地状态，超过截止丢弃并等待后续可恢复内容，不经反向网线通知发送端。若选受控帧内刷新，须验证无反馈损失下的有界恢复能力。CRC坏包、重复、乱序、局部缺失或单帧解码失败不得直接导致进程退出、无限阻塞或每次重启整机；允许隐藏/跳过损坏内容并继续，花屏、冻结和帧龄如实统计。

阶段二启用`feedback_enabled=true`前，必须实际实现并测量反向收发、反馈驱动恢复/有限重传及TDD；重新核算吞吐/资源/截止并签核统一PC/PL/PS/profile。未声明或不支持的反馈能力不得触发板端TX，不允许混用新旧profile后声称兼容。反馈从阶段一延期，不从最终目标删除。

## 1. 分层边界

阶段一只有前向调度周期；保留的`superframe_seq`表示该前向周期序号，不表示已经存在反馈时隙。若主动预留静默窗口，须在阶段一profile中写明并计入吞吐，不能虚报为TDD已实测。阶段二才启用下列TDD结构。

```text
阶段二TDD超帧
 ├─ 前向：公开同步/双TX正交训练/受保护PHY头/双流数据与导频/尾部保护
 ├─ guard：TX停发、射频切换、接收稳定
 ├─ 反向：单流同步/受保护控制头/反馈载荷/CRC
 └─ guard：反向TX停发、恢复双RX、必要重捕获

前向数据 → link包头 + 一个FEC编码符号 + CRC
FEC恢复 → 固定尺寸源符号：视频片段描述 + 原始NAL/slice字节 + 零padding
```

物理帧、RF包、FEC块、slice、AU、HDMI显示帧必须分别命名/计数，禁止混称“帧率”。FEC可跨多个slice/AU，但同一块不能跨session/epoch；不要求一个物理帧等于一个完整视频帧。

## 2. 必须先冻结的PHY profile

当前候选QPSK/4MSPS/1Msym/s，核心固定2×2 MIMO双流和流水线1024×600真实新源帧20fps、约3秒帧龄；不自行改SISO/单流分集、分辨率或帧率，不将候选标成已达标。资源不足先按README列额外功能精简/延期方案及节省、影响，不改变PL数据面归属。profile文件必须含：采样/符号率、RRC rolloff/taps、定点比例/饱和、IQ及天线序、扰码种子/复位范围、位/字节到QPSK映射、双流映射、前导序列、训练顺序、导频位置、PHY头编码、payload长度、物理保护间隔及尾零、前向调度周期、反馈能力标志、时钟/相位跟踪模型。阶段一G0另外冻结周期会话/参数/恢复点策略；阶段二B0才实测冻结反馈PHY、ENSM/UHD切换guard与TDD时隙。

前导用于盲捕获，不用业务帧ID或发送golden决定起点；正交训练须可分别估计4条H，不允许两TX完全相同训练而不能区分。PHY头须在业务载荷前独立可靠恢复，指定profile/session、超帧/物理帧序号、两个流各自有效长度与头CRC；重复/低码率保护开销计入预算。PHY头CRC失败则丢该物理帧并统计，不能用不可信长度驱动缓存/DMA。

双TX独立相位/CFO、公共RX本振与SFO必须有仿真模型，不能仅以AWGN单CFO模型代表实板。头、训练和数据须在相同样本坐标系下解析；锁定首数据同拍和NCO生效点写入golden。

|28|2|symbol_index，0..k-1源，k..n-1修复|
|30|2|payload_bytes，活动profile范围内|

CRC为CRC-32/ISO-HDLC（poly04C11DB7，反射实现EDB88320，init/xorout FFFFFFFF，refin/refout true），范围为32字节头＋实际payload、不含PHY padding，CRC值LE放置。golden至少覆盖空载荷控制、零字节、最大payload、端序、单bit损坏。硬件流水CRC实现与PC同字节序。

数据payload为恰一个固定长度编码符号S，当前候选S=512字节，早期1024B仅保留作历史预算；link payload长度按type/profile决定。纠删码保护整个源符号，包括视频描述；不能将视频头留在未保护区域。坏link CRC不交付源字节，R08依据可信块描述/序号范围识别缺失，不能只靠收到“坏包头”识别擦除。

session/control可不经过数据块FEC，但须独立保护和有限重复。会话描述提供完整profile ID、k/n/S、映射/交织、视频参数和时间基准；板端不因会话描述一次未收到永久停机；阶段一周期广播/接收并有界重捕获，阶段二才允许通过反馈请求重发。

## 4. FEC源符号内的视频头（固定40字节）

|偏移|字节|字段|
|---|---|---|
|0|4|video_frame_id|
|4|8|capture_time_us，摄像头采集时间映射到会话时间|
|12|4|NAL/slice unit_id，会话内单调标识|
|16|4|该unit总字节数|
|20|4|fragment_offset，按字节|
|24|2|fragment_bytes，0..S-40|
|26|2|fragment_index|
|28|2|fragment_count|
|30|1|unit_type：参数/SEI/IDR slice/非IDR slice等|
|31|1|video_flags：AU开始/结束、恢复点等，按schema分配|
|32|4|duration_us，20fps通常50000|
|36|4|reserved/可协商扩展，发送0|

其后fragment_bytes为原始Annex-B或明确定义的NAL封装字节（G0锁定一种），尾部至S补0；FEC保护padding但视频解析不将padding送解码器。unit最大值/每帧slice数/在途块数由协商profile限制，不能无限分配。保留capture_time而非把解码器token当采集帧ID。

PS按unit_id/offset重组，完整slice优先交付；同AU内缺slice可作受损输入，不要求整个AU所有unit齐全才解码。必要头缺失不得伪造原始字节或重算原CRC后宣称恢复；错误隐藏显式记录。slice边界不一定是任意矩形，丢失可能跨帧传播，必须用真实编码器/解码器验证。

## 5. FEC、交织和重传要求

2026-11-03固定8-bank，不再进行16-bank测试/构建/实现或维护双候选，已有历史证据保留。当前每块系统RS k=20/n=32/S512（源比例.625、最多恢复12个擦除）不因bank选择改变；旧k24/n32/S1024仅为历史预算例，不作为并行实现。GF多项式、生成矩阵、修复符号顺序和运算规则在schema/参考实现中锁定，PC/PL均用公共golden验证。最终profile仍须G0冻结，不能把平均丢失率当作块内必恢复保证：评估尾部损失、连续丢包、双流同时损失及实际前向调度间隔；阶段二另测反馈/TDD间隔对FEC与交织的影响。

每块有固定截止/最长等待，达到解码条件立即可恢复输出；原样收到的源符号可提前向PS交付，后续恢复符号去重。超过恢复能力仍尽力交付已有源，块结束/超时输出未恢复索引并释放，不能永远等k包或等整AU齐全。活动存储固定8-bank，须单独验证满队列/最坏恢复突发吞吐、第九任务的有界背压/丢弃、取消重用、排队绝对截止及活动处理期限；单块纠错成功不代表队列达标。交织深度与延迟明确计算，禁止把收包无限攒成池。

阶段一不依赖反馈驱动重传：块截止后释放缓存、记录未恢复索引并等待周期参数/恢复点，不等待反向RF ACK、请求响应或无限补齐。若有固定前向有限重复，须在profile中明确并计入预算。

阶段二重传复用相同block/symbol身份，新packet_seq，且设重试上限、字节预算及播放截止。对已交付符号幂等去重，不产生第二次AU/显示。超过截止丢弃旧块并按需发关键帧/刷新请求；反馈缺失时仍不永久等ACK。
