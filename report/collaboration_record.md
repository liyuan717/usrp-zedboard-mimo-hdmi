# 可见协作记录与纠错轨迹

本文件是当前聊天可见过程及原始测试记录的整理，不是所有历史聊天的完整逐字导出，不包含模型私有推理。

| 用户要求/可见反馈 | 实施或纠错 | 留下的可复用经验 |
|---|---|---|
| 要求新空口，不用旧 IQ/RFD 冒充 | 新 run_id、boot_id、ADC SHA、源/实收文件逐字节与像素比对 | 先定义证据链再判断通过 |
| “我允许你自动重启测试” | 在本用户已授权的有限测试范围恢复干净 RAM | 自动重试范围来自用户，技能不能默认授予其他团队 |
| “先功能闭环，允许降帧率” | 有限收完再播放，保留实际回执速率 | 源 fps、物理 fps、实收吞吐分开 |
| 多次“没来得及确认”“先收回判断” | 未看清轮次不计视觉通过，重显单列 | 物理回执不能替代视觉确认 |
| “角色移动，画面稳定” | Sintel 与 Bunny 两段实际新空口文件验收 | 两种内容排除固定预存画面假通过 |
| 要网页选择原视频、不压缩 | 后台完整 MP4 分块，实收恢复后正常解封装 | 区分不转码和解码所需容器适配 |
| 同 CRC 正确仍失败 | 找到缺 378/379 帧 | 完整性必须检唯一集合及最终文件 |
| 用户问原版本为何失败 | 分开 CRC 错误、漏帧、HDMI 异常与低帧率 | 不将不同阶段失败合并为同一根因 |
| 本次要求完整提交包 | 实际离线依赖追踪，先发现 vendor SHA 不一致，再从原始归档恢复并逐条核对 | 按哈希从后续工程原归档找回精确源码，102 条 vendor/18 项配方匹配 |

提示模板、错误触发和校验脚本在技能包中；模型提供方案，工具及用户观察决定结论。没有完整可见记录支持的细节不补写成事实。

本次可见提示、模型回答和打包自纠的具体摘录见 [协作案例](collaboration/readme.md)。
